# MiniRTOS-Linux ML Classifier

## Purpose

This folder contains the Phase 22 ML tooling for MiniRTOS-Linux.

The ML layer trains a lightweight supervised anomaly classifier from the synthetic dataset generated by:

```text
ai-analyzer/training/generate_dataset.py
```

The ML layer does not replace the deterministic analyzer or explainable rule-based anomaly detector. It adds a trained-model prediction layer on top of the existing analysis pipeline.

## Model Type

Current model:

```text
RandomForestClassifier
```

Why this model was chosen:

- Works well on tabular features.
- Handles nonlinear feature interactions.
- Does not require a large deep-learning pipeline.
- Supports `predict_proba` for confidence output.
- Easy to save and load with `joblib`.
- Easy to explain in interviews.

## Train the Model

Generate scenario logs and dataset first:

```bash
docker compose up --build demo
docker compose run --rm training-dataset
```

Then train locally:

```bash
python3 ai-analyzer/ml/train_model.py   --dataset reports/generated/synthetic_dataset.csv   --model-output models/anomaly_classifier.joblib   --label-encoder-output models/label_encoder.joblib   --metrics-output reports/generated/model_metrics.json
```

Docker:

```bash
docker compose run --rm ml-train
```

Expected generated files:

```text
models/anomaly_classifier.joblib
models/label_encoder.joblib
reports/generated/model_metrics.json
```

## Predict From Runtime Log

```bash
python3 ai-analyzer/ml/predict_model.py   --model models/anomaly_classifier.joblib   --label-encoder models/label_encoder.joblib   --log logs/task_crash_runtime_logs.jsonl   --window-ms 5000
```

This path converts runtime log events into windowed feature rows, then predicts labels for each window.

---

## Analyzer Integration

`analyze.py` supports optional ML output:

```bash
python3 ai-analyzer/app/analyze.py   --log logs/task_crash_runtime_logs.jsonl   --window-ms 5000   --ml-model models/anomaly_classifier.joblib   --ml-label-encoder models/label_encoder.joblib
```

If no ML flags are passed, the analyzer keeps its existing deterministic and rule-based behavior.

If an ML model path is provided but artifacts are missing, the analyzer prints a clean skipped message rather than crashing.

## Limitations

- The model is trained on synthetic scenario telemetry.
- Labels are scenario-derived and may not perfectly describe every individual time window.
- The classifier is not production-validated.
- Accuracy on a small synthetic dataset should be interpreted carefully.
- The model does not replace deterministic safety checks or watchdog logic.

---

## Interview Talking Point

```text
The ML classifier is trained from runtime telemetry generated by the simulator itself. The C++ runtime emits JSONL logs, the Python training generator converts those logs into window-level features and labels, and the ML script trains a Random Forest classifier that predicts anomaly labels with confidence scores. I kept the rule-based detector as an explainable baseline and added the trained model as an optional additional analysis layer.
```
